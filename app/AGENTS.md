## Version-critical facts — these contradict what you remember

| Fact | Consequence |
|---|---|
| `src/app` takes precedence over root `app/` | A stray root `app/` is silently ignored |
| Auth gating is `<Stack.Protected guard={…}>` | NOT `useEffect` + `useSegments` + `router.replace` |
| `useAnimatedGestureHandler` is **REMOVED** | Use gesture-handler 2 `Gesture.Pan()` |
| Worklets live in `react-native-worklets` | Babel plugin is auto-configured by `babel-preset-expo` — **never hand-add one** |
| `@react-navigation/*` imports fail from app code | Import from `expo-router/react-navigation` |
| New Architecture is always on (SDK 55+) | Never write `newArchEnabled: false` |
| `presentation: 'formSheet'` + `sheetAllowedDetents` is native | **No bottom-sheet library.** Use it for profile + filter sheets |
| typedRoutes forbids relative hrefs | `href={{ pathname: '/user/[id]', params: { id } }}` |
| React Compiler is beta | **Never mutate objects/arrays in place** — the #1 breakage. Escape hatch: `"use no memo"` |
| Expo Go is not viable | Development build required on both platforms |

**Reanimated 4 naming:** prefer `scheduleOnRN` / `scheduleOnUI` over `runOnJS` /
`runOnUI`, and `useScrollOffset` over `useScrollViewOffset`. Note `runOnJS` is
still exported and still compiles — this is a **review rule, not a compiler
error**. Grep for it.

## Tabs — native, always

Import from **`expo-router/unstable-native-tabs`**.

`expo-router/tabs` and `expo-router/js-tabs` are the same JS implementation —
neither is native. Native tabs are only at the `unstable-` path in SDK 57
(renamed to `expo-router/native-tabs` in SDK 58; expect one import rewrite).

Four tabs, and only four: **Home · Match · Chat · Profile**.
Search and Likes are Home *header* entries, never tabs.

## NativeWind v5 — RC, and not like v4

Most NativeWind knowledge in training data is v4 and is **wrong here**.

- **No `babel.config.js`.** The `nativewind/babel` preset is removed in v5.
- **No `tailwind.config.js`.** Config is CSS-based, in `global.css`.
- `withNativewind(config)` in `metro.config.js` — wrap Expo's config, never replace it.
- **`cssInterop` and `remapProps` do not exist.** Use `styled` from `nativewind`.
- `global.css` is imported **once**, in `src/app/_layout.tsx`. That import is the
  only thing that wires Metro to the CSS — there is no `input` option.
- `lightningcss` is pinned to `1.30.1` via `overrides`. Leave it pinned.
- `nativewind-env.d.ts` is regenerated by Metro. Do not hand-edit.

## Architecture rules

- **One component per file, one folder per component.**
- **Named exports everywhere** except route files, which need a default.
- **Never create an empty folder.** Create it when the first file lands in it.
- **Route files are never moved or renamed.** A file's path IS its route.
- **No bare RN primitives** (`View`, `Text`, `Pressable`, `Image`, `ScrollView`,
  `FlatList`, `TextInput`) outside `components/common/atoms/`. Use the wrappers.
- **A text wrapper never nests inside another text wrapper.** A bold word inside
  a sentence uses a plain `Text`.
- Data flow is **screens → hooks → Zustand stores → mock service layer**.
  **No TanStack Query** until the real backend lands.
- Theme: light and dark from day one, every value a semantic token,
  **zero hardcoded styles**.

## Product constraints that change the code

These are positioning, not preferences. Violating one is a bug.

- **No photos. Anywhere.** Users are a **preset avatar** only. No upload, crop,
  gallery, camera, or photo verification. Do not reach for `expo-image-picker`.
  Interests + bio carry the card instead.
- **Platonic friends only. No romance framing** in copy, fields, matching or
  imagery. "Romantic or flirty advance" is an explicit *report reason*.
- **18+ hard stop.** An under-18 birthday goes to a dead-end screen with no way
  forward. The age filter floors at 18.
- **Messaging is match-gated.** Like + optional note → request → accept → thread.
  There is no open messaging.
- **"Hello" is a placeholder name.** Keep the product name out of all
  user-facing copy; all strings live in `src/copy/`.
- **Voice calls only**, fully mocked. No video, no WebRTC, no mic permission.
- Distance is **km**, via one centralised formatter.
- Out of scope for v1: groups, events, video calls, undo/rewind, superlike,
  map view, incognito, i18n, real ads, real billing, real backend.

## Verification platform — Android only

**Verify on Android. Do not attempt iOS builds or sweeps.** Operator decision,
2026-09-19.

iOS cannot build on this machine: `expo-modules-jsi@57.1.0` is incompatible with
Xcode 26.2 on two counts (see PLAN.md parking #16). Rather than carry a growing
patch set against a vendored module, iOS verification is deferred until the
toolchain is sorted.

Consequences:
- Every phase's verification block is **Android-only**. An iOS row stays `[!]`.
- "Both platforms 100%" cannot be ticked. That is expected, not a failure.
- `npx expo run:ios` and any simulator command are out of scope. Do not run them.
- `scripts/patch-expo-modules-jsi.js` stays, but it is iOS-only and inert here.
- PLAN's "never compare iOS against Android" still holds — there is simply only
  one platform to compare against itself.

## Hard rules

- **Never run a version-control command.** No commits, no branches, no staging.
  Work is left in the working copy for its owner. *Consequence: copy a file
  before any destructive edit — "revert to last commit" is not available.*
- **Verify after every step.** Cheap one step back, expensive twenty steps back.
- **Park what you find; never stop for it.** You broke it → fix it. You found it
  broken → log it in PLAN.md §8 and carry on.
- **Never run both simulators at once.** Heat, ambiguity, memory, stale state.
- **Navigate to every route by hand on both platforms.** A screen can vanish
  while the build stays green, with no error anywhere.
